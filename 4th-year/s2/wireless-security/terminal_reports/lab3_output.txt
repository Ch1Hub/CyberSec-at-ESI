  CRYPTOGRAPHIC ANALYSIS:

  PMK (Pairwise Master Key):
    PMK = PBKDF2-SHA1(passphrase, SSID, 4096 iterations, 256-bit)

    • PBKDF2 with only 4096 iterations is WEAK by modern standards
    • GPU (hashcat) can compute ~1M+ PMK candidates/second
    • GTX 4090 tests ~2.5M PMK/sec for WPA2

  PTK (Pairwise Transient Key):
    PTK = PRF(PMK, "Pairwise key expansion", MIN(AA,SPA)||MAX(AA,SPA)||
              MIN(ANonce,SNonce)||MAX(ANonce,SNonce))

    • PTK is 384 bits: KCK (128) || KEK (128) || TK (128)
    • MIC in Message 2 = HMAC-SHA1(KCK, SNonce||EAPOL payload)
    • Attacker verifies each passphrase guess against known MIC

  VULNERABILITIES EXPLOITED:
    • Offline attack: no interaction with live AP needed after handshake capture
    • No rate-limiting: unlimited password guesses
    • Weak passphrase: "P@ssw0rd123" is in rockyou.txt
    • PBKDF2 iteration count (4096) is trivially low
    • SSID known → precomputed rainbow tables (PMKID lists) possible

  DEFENSIVE RECOMMENDATIONS:
    • Use WPA3-SAE (Simultaneous Authentication of Equals)
      → dragonfly handshake resistant to offline dictionary attacks
    • Minimum 20-char random passphrase (uppercase + lowercase + digits + symbols)
      → entropy > 120 bits
    • Use WPA2-Enterprise (802.1X/EAP-TLS) with RADIUS for per-user credentials
    • Enable 802.11w (Protected Management Frames) → prevent deauth injection
    • Disable WPS (Wi-Fi Protected Setup) → PIN brute-force vulnerability
